## 1. 実験の目的

v4 では「classroom > tutoring」という逆転結果が得られた。しかし v4 は学習者を均質なエージェントとして扱っていた。Bloom の 2 Sigma Problem の本質は「1on1 tutoring が heterogeneous な学習者集団で特に有効」というものである。

v5 では以下の問いを検証する：

> **learner heterogeneity を明示的にモデル化した場合、tutoring の優位性は現れるか？**

---

## 2. 実験設計

### 2.1 4条件の設計

| 条件 | 教育形式 | learner profiles |
|------|---------|-----------------|
| no_education | なし | プロファイルなし |
| homogeneous_classroom | 1:N 共有授業 | 全員 medium ability, 同一誤概念 (forgets_edge_cases) |
| heterogeneous_classroom | 1:N 共有授業 | mixed: high/medium/low ability, 異なる誤概念 |
| 1on1 tutoring | 個別 4 exchange | heterogeneous と同一プロファイル |

tutoring 学習者は heterogeneous_classroom と**同一プロファイル**を使用。条件間の直接比較を可能にするため。

### 2.2 Learner profiles の詳細

**Homogeneous class（4名、全員同一）:**  
ability=medium, interest=worked_examples, misconception=forgets_edge_cases, attention=medium

**Heterogeneous class / Tutoring（同一プロファイルを使用）:**

| # | ability | misconception |
|---|---------|---------------|
| 1 | high | none |
| 2 | medium | forgets_edge_cases |
| 3 | low | applies_modifiers_before_activation |
| 4 | medium | thinks_blue_always_active |

### 2.3 Tutoring の特徴（v4 から継続）

4 exchange（8ターン）：opener → response → 診断Q1 → 回答 → **フィードバック（誤概念修正）** → 反省 → 診断Q2 → 最終回答

チュータープロンプトにはプロファイルが渡され、学習者の誤概念を明示的に修正するよう指示。

## 5. 考察

### 5.1 Bloom 仮説は v5 でも支持されない

tutoring (38%) < heterogeneous_classroom (41%) という逆転は v4 からの傾向と一致する。プロファイルを明示的に設計し、チューターが誤概念を修正するよう指示しても、classroom を上回ることはできなかった。

### 5.2 Heterogeneity Penalty の確認

homogeneous (44%) > heterogeneous (41%) — 学習者が混在するクラスでは平均スコアが低下した。これは Bloom の観察と一致する：**heterogeneous なクラスでは全員に最適な授業ができない**。

ただし差は 3 ポイントと小さく、n=4 では統計的に意味のある差とは言えない。

### 5.3 Tutoring の高 Variance が示すもの

tutoring の std dev (0.177) はすべての条件で最大。個人内訳を見ると：

- 最高: thinks_blue_always_active のある medium 学習者 → 5/8 (tutoring)  
- 最低: forgets_edge_cases + applies_modifiers の learner → 2/8 (tutoring)

チューターが「誤概念を修正できた学習者」と「できなかった学習者」の差が大きい。**tutoring は効く人に非常に効くが、効かない人には効かない**という特徴が現れている。

classroom の variance は均質クラスで 0.125、混在クラスで 0.063 と低い。classroom は「均一な中程度の効果」を全員に与える傾向がある。

### 5.4 最も改善した誤概念：thinks_blue_always_active

この誤概念を持つ学習者は hetero_classroom で 3/8、tutoring で 5/8 を達成。これが tutoring の「当たり」の学習者。

tutoring プロンプトに「CRITICAL: Blue tokens are always active regardless of Green position — このミスを明示的に修正すること」という指示があった。この誤概念は具体的な診断・修正が可能だったと考えられる。

逆に applies_modifiers_before_activation を持つ学習者は tutoring で 2/8 に留まった（hetero_classroom では同じプロファイルの学習者が 4/8）。このミスは「ルールの適用順序」という手続き的な知識に関わり、短いセッションでの修正が難しかった可能性がある。

### 5.5 Classroom が L4 debugging で強い

l4_debug_01 と l4_debug_02（debugging タスク）では classroom が 4/4 = 100% を達成した一方、tutoring は 1/4 = 25%。

classroom の公開授業では教師がルールを体系的に説明し、複数学習者の質問を通じてデバッグ的な思考が促進されたと考えられる。tutoring では 4 exchange という制約の中でカバーできなかったタスクタイプがあった可能性。

### 5.6 low ability 学習者の逆転現象

heterogeneous_classroom の low ability 学習者（applies_modifiers_before_activation）が 4/8 を達成。これは同クラスの high ability 学習者（3/8）を上回る。

one_on_one tutoring の同プロファイル学習者は 2/8 に留まった。

この「逆転」の原因として考えられるのは：
- classroom のグループ Q&A では他の学習者（high ability）が提起した質問から benefit を受けた
- tutoring では同じ誤概念に対して tutor が集中的に時間を使ったが、十分に修正できなかった
- applies_modifiers_before_activation は複数ルールの順序理解を要求し、短期修正が困難

### 5.7 v4 との比較

| 項目 | v4 | v5 |
|------|-----|-----|
| classroom 条件 | 1条件 (classroom) | 2条件（homo/hetero） |
| classroom 正解率 | 47% | homo: 44%, hetero: 41% |
| tutoring 正解率 | 28% | 38% |
| classroom vs tutoring | classroom 優位 | classroom 優位（継続） |
| heterogeneity_penalty | 測定不可 | 確認（-3pp） |
| tutoring under hetero | 測定不可 | 確認されず |

v5 では tutoring の正解率が v4 (28%) より高くなった (38%)。プロファイル適応とフィードバックループが一定の効果を示した可能性があるが、classroom を超えるには至らなかった。

## 6. 方法論的課題

### 6.1 レポートの既知バグ

`detect_ceiling` と一部の集計が旧条件名 `'classroom'` を参照しており、v5 の実際の条件名 `'homogeneous_classroom'` / `'heterogeneous_classroom'` と不一致。そのため：

- Score by Task Type の「Classroom Correct%」が 0% と誤表示
- Token metrics の「Tutoring gain +37.5pp」は 0% を基準にしているため誤り

実際の tutoring gain は tutoring(38%) - hetero(41%) = -3pp（劣位）または tutoring(38%) - homo(44%) = -6pp。

### 6.2 プロファイルモデルの限界

LLM エージェントに「low ability」プロファイルを与えても、基礎となるモデル（Sonnet 4.6）の能力自体は変わらない。プロファイルはプロンプト上での振る舞いを変えるだけであり、本当の能力差を表現しているわけではない。

「low ability 学習者がなぜ hetero_classroom で高得点を取るのか」という現象は、LLM がプロンプト上で low ability を演じながらも、underlying reasoning は同じモデルで行われているという矛盾から生じる可能性がある。

### 6.3 tutoring session の coverage 不均一性

4 exchange の tutoring では、tutor がどのルールをカバーするかが動的に決まる。同じプロファイルを持つ学習者でも、tutor の対話によって学ぶルールが異なる。これが tutoring の高 variance の一因。

classroom は固定の共有講義なので、全学習者が同じ内容を受ける。

## 7. 次の実験への提案

| 優先度 | 提案 | 理由 |
|--------|------|------|
| 高 | **n を増やす（n=8〜10/condition）** | n=4 では 1人の差が 3pp を動かす |
| 高 | **レポートの条件名バグを修正** | detect_ceiling が 'classroom' を参照している |
| 中 | **tutoring session log を分析** | tutor がどの誤概念を修正したか、実際のトランスクリプトを確認 |
| 中 | **mastery criterion の実装** | 「正答するまで tutoring を継続」ループを追加 |
| 低 | **applies_modifiers_before_activation の対応を強化** | この誤概念は短期修正が難しい — tutoring prompt の改善 |

### レポートバグの修正方針

`detect_ceiling` と `build_markdown` の `'classroom'` 参照を以下に変更：

```ruby
# 現在（バグ）
c_pct = avg_correctness(type_rows.select { |r| r['condition'] == 'classroom' })

# 修正案
classroom_conditions = ['classroom', 'homogeneous_classroom', 'heterogeneous_classroom']
c_pct = avg_correctness(type_rows.select { |r| classroom_conditions.include?(r['condition']) })
```

## 8. 結論

**v5 の核心的知見：**

> 学習者プロファイルを明示的にモデル化し、チューターがプロファイルに基づいて誤概念を修正するよう設計しても、1on1 tutoring が 1:N classroom を上回ることは n=4 の実験では確認されなかった。

**新たに確認できたこと：**
1. **Heterogeneity Penalty が存在する** — 混在クラスでは均質クラスより平均スコアが下がる（-3pp）
2. **Tutoring の Variance が最も高い** — 誤概念によって tutoring の効果が大きく異なる
3. **thinks_blue_always_active の修正は tutoring で有効** — この誤概念を持つ学習者は 5/8 を達成
4. **applies_modifiers_before_activation は tutoring でも改善困難** — 手続き的知識の修正は難しい

**Bloom の理論との関係：**  
この実験は Bloom の理論を否定するものではない。現在の tutoring 実装（mastery criterion なし、単発セッション、LLM エージェントによる擬似的なプロファイル）は、Bloom が研究した tutoring とは根本的に異なる。真の mastery learning ループを実装した上で n を増やすことが、Bloom の仮説を公平に検証する次のステップ。
