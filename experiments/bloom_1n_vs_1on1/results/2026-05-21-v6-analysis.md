## 1. 実験の目的

v5 では「プロファイル」（ability/misconception/interest の属性値）を学習者プロンプトに埋め込む方法を用いたが、LLM の基礎能力は変わらないためプロファイルがほぼ機能しなかった。また、条件間で同一プロファイルを使いまわしており、1on1 と hetero_classroom の比較が本質的に「同じ学習者への異なる教育形式」になっていた。

v6 では以下の設計変更を行い、同じ問いを再検証する：

> **理論駆動の learner type を post-LLM メモリ制約として実装した場合、1on1 tutoring の優位性は現れるか？**

### v6 の主な設計変更点

1. **7 種の learner type**（rule_extractor, edge_case_dropper, order_confused, answer_first, help_seeker, passive_listener, example_memorizer）を導入。各 type はプロンプト上のロールプレイではなく、LLM 生成後のメモリに対してハードな制約として適用される。

2. **Post-LLM 制約の内容：**
   - `edge_case_retention`: エッジケースを確率的に脱落させる（edge_case_dropper = 10%）
   - `rule_order_retention`: ルール順序を確率的にシャッフル（order_confused = 20%）
   - `memory_budget_words`: メモリ語数の上限（passive_listener = 80 語）

3. **Tutoring の診断ループ**: 交換 3 でチューターが誤概念を特定・修正、交換 4 で再テスト（v5 の「フィードバック → 反省」から「診断修正 → 再テスト」へ）

4. **Condition assignments の非対称設計:**
   - homo_classroom: 全員 `edge_case_dropper`（最もシンプルな均質条件）
   - hetero_classroom / 1on1: `[rule_extractor, edge_case_dropper, order_confused, passive_listener]`

## 5. 考察

### 5.1 Bloom 仮説は v6 でも支持されない

1on1(59%) = hetero_classroom(59%) という結果は、同一 type 構成での直接比較においても tutoring の優位性が現れなかったことを示す。さらに homo_classroom(94%) との比較では 1on1 は大幅に劣位。

v4・v5 から継続する「classroom ≥ 1on1」というパターンが、v6 の型制約導入後も維持されている。

### 5.2 Type 別の 1on1 効果の非対称性

hetero_classroom と 1on1 を同一 type 構成で比較すると、**互いに打ち消し合う効果**が見られた：

**1on1 が助けた型：**  
passive_listener: hetero(13%) → 1on1(38%) **+25pp**  
passive_listener は classroom では質問スキップ（質問確率 0%）により学習セッションが非常に薄い。1on1 では個別にチューターが接触するため、学習量が実質的に増加した。

**1on1 が悪化させた型：**  
order_confused: hetero(88%) → 1on1(63%) **−25pp**  
order_confused のメモリはルール順序が高確率（80%）でシャッフルされる。hetero_classroom の共有講義では全員に対して体系的にルールが提示されたため、order_confused でも構造が伝わりやすかった可能性がある。一方 1on1 では診断・修正の会話が特定の誤概念に集中し、ルール全体の順序整理が行われにくかったと考えられる。

**変化がなかった型：**  
rule_extractor と edge_case_dropper は両条件で 63%・75% と全く同じスコア。これは memory 制約後の内容が evaluator の採点に支配的であることを示唆する（教育形式の差がスコアに表れていない）。

### 5.3 Homogeneous Classroom の圧倒的優位

homo_classroom(94%) の高スコアは次の構造によって生まれた：

1. 教師へのコンテキスト「全員 edge_case_dropper ——エッジケースを強調して教えよ」という型特化指示
2. 全員同一型のため、授業内容が 4 名全員に最適化された
3. edge_case_dropper の edge_case_retention = 10% という制約があるにもかかわらず、メモリ語数（80〜87 語）でも十分なパフォーマンスを発揮

これは Bloom の洞察の**逆説的な検証**である：Bloom は「tutoring が classroom を上回る」と主張したが、その背景には「classroom が heterogeneous な学習者に対して最適化されていない」という前提がある。**homogeneous な集団に特化した classroom は非常に高効率**という含意が、今回の設計から確認された。

### 5.4 非対称アサイン設計の問題

本実験は意図的に homo_classroom と hetero_classroom/1on1 を**異なる type 構成**で設定した（前者は全員 edge_case_dropper、後者は 4 type 混合）。これは「均質クラスには最適化教授、混合クラスには汎用教授」という現実的な教育状況を模倣するためである。

しかしこの設計では 3 つの変数が同時に変化している：
1. 学習者の type 構成（homo vs hetero）
2. 教師への指示内容（型特化 vs 混合型汎用）
3. 教育形式（classroom vs 1on1）

「教育形式の効果」を純粋に測定するには、hetero_classroom と 1on1 の比較（type 構成が同一）が最も適切であり、その結果は **59% = 59%（差なし）** であった。

### 5.5 v5 との比較

| 項目 | v5 | v6 |
|------|-----|-----|
| 学習者差異のモデル化 | プロンプト上のロールプレイ | Post-LLM メモリ制約（ハード） |
| homo_classroom 正答率 | 44% | **94%** |
| hetero_classroom 正答率 | 41% | 59% |
| 1on1 tutoring 正答率 | 38% | 59% |
| hetero vs 1on1 の差 | hetero > 1on1（+3pp） | 同率（0pp） |
| 誤解修正率（1on1） | 測定なし | 75% |
| 条件内 Variance 最大 | 1on1（std=0.177） | hetero_classroom（std=0.329） |

v6 では全体的なスコアが上昇（v5 の最高 44% → v6 の homo 94%）。Post-LLM 制約による型差異の実装が有効に機能し、passive_listener(13%)〜rule_extractor(63%)という範囲で意味のある分布が生まれた。

v5 から続く「1on1 ≤ classroom」パターンは v6 でも維持されているが、「tutoring が苦手な型を引き上げ、得意な型を下げる」という**均質化効果**が初めて定量的に確認された。

### 5.6 誤解修正と最終スコアの乖離

1on1 の誤解修正率は 75%（3/4 が corrected_misconceptions を持つ）だが、order_confused の 1on1 スコアは hetero_classroom より低かった。これは：

1. 誤解修正プロセス（diagose → correct → retest）は主に明示的な誤概念（例: 特定ルールの誤適用）を対象とする
2. order_confused の主な障害は**ルール適用順序**であり、これは「誤概念」というより手続き的な記憶の問題
3. rule_order_retention = 20% による順序シャッフルは、tutoring の誤解修正ループでは修復できない

tutoring が有効なのは「明示的な命題的誤解（X は常に Y である、という誤った信念）」に対してであり、「手続き的順序の混乱」には効きにくいという示唆。

## 6. 方法論的課題

### 6.1 n=4 の統計的限界

各条件の学習者は 4 名。per-learner の 1 問の差が 3.1pp を動かす。今回の order_confused の −25pp 差（hetero vs 1on1）は 2 問分の差に過ぎず、統計的有意性は確認できない。

### 6.2 アサイン設計の交絡

homo_classroom は「edge_case_dropper に最適化された授業」を受けており、純粋な「教育形式の比較」ではない。homo vs hetero の差（94% vs 59%）は型構成の差と指示の差が混在している。

### 6.3 rate limit による割り込み

実験中に 2 回のトークンレート制限が発生し、合計 11 時間の待機が生じた。LLM の状態は変わらないが、非常に長い実験ランが必要になることが確認された。

## 7. 次の実験への提案

| 優先度 | 提案 | 理由 |
|--------|------|------|
| 高 | **n を増やす（n=8〜10/condition）** | n=4 では type 別の差が統計的に意味を持たない |
| 高 | **order_confused への特化対応** | tutoring prompt に「ルール適用順序を明示的に確認せよ」という指示を追加し、再検証 |
| 中 | **同一 type 構成の homo_classroom を設定** | 全員 rule_extractor の classroom を作り、rule_extractor の 1on1 と比較 |
| 中 | **mastery criterion の実装** | 再テストで正解するまで tutoring を継続するループを追加 |
| 低 | **高確信・誤答（14%）の分析** | どの type・task で over-confidence が起きているかを確認 |

## 8. 結論

**v6 の核心的知見：**

> 理論駆動の learner type を post-LLM メモリ制約として実装し、tutoring に診断-修正-再テストループを追加した条件でも、1on1 tutoring が classroom を上回ることは n=4 では確認されなかった（1on1 = hetero_classroom = 59%）。

**新たに確認できたこと：**

1. **passive_listener は 1on1 で改善する**: classroom での完全スキップ（13%）から、個別接触（38%）へ +25pp
2. **order_confused は 1on1 で悪化する**: hetero_classroom（88%）→ 1on1（63%）−25pp。手続き的順序の問題は tutoring の誤解修正ループでは修復されにくい
3. **1on1 は variance を圧縮する**: hetero_classroom（std=0.329）> 1on1（std=0.157）。tutoring は「最弱者を引き上げ、最強者を下げる」均質化効果を持つ
4. **誤解修正率（75%）とスコアは乖離しうる**: 修正の対象となる誤解の種類が、最終テストの成否を決める

**Bloom の理論との関係：**  
Bloom が観察した 2 Sigma 効果は「mastery learning criterion を持つ tutoring と、uniform pace の classroom の比較」に基づく。本実験の 1on1 は 4 exchange の固定セッションであり、mastery criterion がない。真の Bloom 検証には再テスト合格まで繰り返す適応的ループが必要であり、それが次のステップとなる。
