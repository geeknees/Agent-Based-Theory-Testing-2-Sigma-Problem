---

## 1. 実験の目的

v7 までの実験では「前提知識なし→授業/1on1」を比較し、一貫して classroom が 1on1 を上回った（classroom_advantage_under_homogeneity）。

v8 では **前提講義を全条件で共通化（flipped learning 設計）** し、「前提知識がある状態での Phase 3 インタラクション」の効果を切り分ける。

**中心的な問い：** 前提知識が確立された後では、議論系（全体討論・小グループ）と 1on1 補修のどちらが学習アウトカムを高めるか？

| 条件 | Phase 3 の内容 |
|------|--------------|
| `lecture_only` | Phase 3 なし（講義＋評価のみ） |
| `lecture_plus_whole_class_discussion` | 全員で 1 問を議論（モデレーター進行） |
| `lecture_plus_small_group_discussion` | 2 人ペアで議論＋共有メモ作成 |
| `lecture_plus_one_on_one_tutoring` | マスタリーチェックのエラー対象に 1on1 補修 |

全条件で共通：
- **Phase 1:** 同一の完全網羅型前提講義（ルール・例・よくある誤り全網羅）
- **Phase 2:** 3 問マスタリーチェック（自動採点、不正解→corrective note をメモリに追記）

## 4. 考察

### 4.1 WCD が最高スコアを示した理由の仮説

whole_class_discussion（83%）が最高だった理由として 3 つを考える。

**仮説①: 観察学習の効果（passive_listener に有利）**  
WCD の passive_listener は 9/10（90%）と全 type_key × 条件の中で最高クラス。全体討論では他学習者の推論を「観察」するだけで十分な学習が得られる。これは Bloom の "observational learning" と整合する。

**仮説②: マスタリーチェック時点での優位**  
WCD 条件は入室時のマスタリーチェック誤答が 1/12 のみ（他条件より少ない）。初期状態の差が結果に影響している可能性がある。

**仮説③: モデレーターによる正答確認の直接的効果**  
WCD の討論クローズで moderator が「正しいスコアは X です」と明示する。この直接的フィードバックが記憶更新を促進した可能性。

### 4.2 1on1 tutoring が「均一化」に優れる理由

1on1 は分散最小（SD=0.05）で、全 4 名が 7〜8/10 の狭い帯域に集中。これはエラーターゲット型補修の特性——誤りを持つ学習者を引き上げることに特化しているため、上振れは少ないが下振れも防ぐ。

**Bloom の 2-sigma 問題との接続:** 1on1 の「底上げ」機能は確認されたが、今回は前提講義が共通なため全条件の底が上がっており、1on1 の追加効果は相対的に小さい（+8pp over lecture_only）。

### 4.3 SGD のパラドックス

SGD は最低スコア（68%）でありながら最高の誤概念修正率（75%）を示す。この矛盾の解釈：

- ペア議論は「誤りに気づく」プロセスを促進するが、**誤りを「正しく修正する」には至らない**ケースがある
- メモリの edge_case 保持率が 0%（SGD のみ）——ペアが edge case を議論のテーマに選ばなかったため
- passive_listener が SGD で最低（3/10）——ペア相手に引っ張られる構造では passive_listener の学習が不安定

### 4.4 lecture_only が SGD を上回ったことの意味

前提講義の質が十分高ければ、追加インタラクションなしでも 70% を達成できる。SGD の 68% はこれを下回っており、**相性の悪い組み合わせ（ペア＋passive_listener）が全体を引き下げた**と考えられる。

## 6. 限界と解釈上の注意

1. **n=4/条件**——統計的有意性の検定は不可。条件間の差は参考値。
2. **講義長のばらつき**（11k〜18k chars）——lecture_only が最短であり、lecture_only のスコアを低く見せた可能性がある。
3. **マスタリーチェック時点の条件差**——WCD は入室前から理解が深かった（誤答 1/12）。この初期差の影響を切り離せていない。
4. **LLM エージェントは人間の学習者ではない**——learner type による制約は人間の認知特性を模倣しているが、実際の学習ダイナミクスとは異なる可能性がある。
5. **Token 数の推定**——chars/4 による概算。実際の API token 数と ±20% の差がありうる。

## 7. 次のステップ（優先順）

| 優先度 | 内容 | 理由 |
|--------|------|------|
| ★★★ | **n を増やして再実行**（n=8〜16/条件） | 現在の条件差（83% vs 68%）が偶然かどうか判断できない |
| ★★★ | **lecture 長を統制**（同一 lecture を全条件で共有） | 条件間の講義長ばらつきを排除する |
| ★★ | **passive_listener × SGD の組み合わせを深掘り** | SGD が passive_listener を「引き下げる」機構を特定する |
| ★★ | **short_rule_induction (L6) の設計見直し** | 全条件 0%——タスク設計またはメモリ表現に問題がある可能性 |
| ★ | **WCD の観察学習効果を独立検証** | passive_listener を WCD 専用実験で検証する |
| ★ | **no_prep baseline 条件を追加** | v7 との比較を正確にするため「前提講義なし」条件を追加 |
