## 要旨

大規模言語モデル(LLM)エージェントは、社会科学研究における被験者の代替として提案されることが増えている。人間の参加者より安価で、速く、制御しやすいからである。本研究は、そうしたエージェントが教育理論 — ベンジャミン・ブルームの「2シグマ問題」、すなわち1対1のマスタリー・チュータリングが集団指導より約2標準偏差高い学習成果をもたらすという主張 — の**真の検証台**になりうるかを問う。7つの設計世代(v3–v9c2)を通じて、「学習」を教育フェーズのトランスクリプトから条件固有のコンパクトなメモリが形成されることとして操作化し、モデルが事前知識から答えることを防ぐ厳格なメモリのみのプロトコルのもとで、合成ルールドメイン(*Zarn Tokens*)上で評価した。

本研究は2つの貢献を報告する。第一に、**LLMエージェントにおける否定的結果**である。すべての世代で集団指導は1対1のチュータリングと同等かそれを上回り、最も厳密な実験(v9c2、学習者154名、240万トークン)では教育条件間の差が10パーセントポイントに収縮した一方、*学習者タイプ*間の差は38ポイントに達した。ブルームの社会的相互作用の優位性は、このエージェント環境では頑健に再現されなかった。前の世代(v9c、37ポイントの差)で大きな討論効果に見えたものは、統制されていない前提知識の交絡に大部分が帰せられると論じる(この帰属が ablation ではなく単一の前後比較に依拠している点は §8–§9 で率直に述べる)。第二に、より永続的な貢献として、**交絡を意識した方法論**を示す。自分たちのパイプラインに対する独立監査によって5つの交絡ファミリ(F1–F5。うち1つは下位交絡に分解され、具体的な脅威は計7つ)を洗い出した — 静的な訂正フィードバック、完全一致採点のアーティファクト、討論エージェントへの文脈注入の欠落、疑似反復、単一インスタンスの役割エージェントおよび学習予算の非対称性である。これらはエージェントによる理論検証において効果量を密かに膨らませる。是正のレシピ(A0/A3/A4/A5/A6/A8)を提示する。そこには真の反復を実現する*母集団増殖*設計と、操作フェーズの前に前提知識を統制する*readiness ゲート*が含まれる。これらの交絡は本研究に固有のものではなく、LLM エージェントで社会科学的主張を検証するというより広い試み全体にとって構造的なリスクであること、そしてそうした統制のもとで得られた否定的結果それ自体が有益であることを主張する。

## 1. はじめに

LLM を*シリコンの被験者*として扱う研究が増えている。経済ゲーム、意識調査、社会シミュレーション、教育において人間の参加者の代わりを務める生成エージェントである。魅力は明らかだ。エージェントの母集団は数分で生成でき、完全にログが残り、人間では倫理的に不可能な反実仮想の操作のもとで何度でも再実行できる。LLM エージェントが既知の人間の知見を再現するなら理論探索の高速ループが得られるし、乖離するならその乖離自体が診断的でありうる。

この約束は、めったに検証されない前提の上に立っている。**作られたエージェント実験が、それが測ると称する構成概念を実際に測っている**という前提である。本論文は、単一の明確に定式化された理論に対して、その前提を反証しようとする持続的な試みである。

対象にはブルームの**2シグマ問題**(Bloom, 1984)を選んだ。ブルームは、マスタリー学習の条件下で1対1の指導を受けた生徒が、従来型の30対1の教室の生徒より約2標準偏差高い成績を示したと報告した。この差は、個別指導群の下位が従来群の上位とほぼ一致するほど大きい。この知見は数十年にわたって教育工学研究を形作り、今日では AI チューターを動機づける根拠として頻繁に引かれる。またこれは**構造的な**主張でもある — クラスサイズ、個別化、能動的関与についての主張であり、だからこそエージェントによる操作化の自然な候補になる。構造変数(誰が誰と話すか、集団がどれだけ大きいか、各学習者がどれだけ参加するか)は、エージェントの実験装置が明確に操作できる変数そのものだからである。

したがって中心的な問いは2層になる。

1. **実質的な問い:** ブルームの理論の構造的条件を LLM エージェントの教育セッションとして操作化したとき、チュータリング/小集団の条件は、大集団や講義の条件より測定可能なほど優れた下流の問題解決を生むか。
2. **方法論的な問い:** その答えを信頼できるか。エージェントによる理論検証を内的妥当性のあるものにするには何が必要か。

第一の問いには否定で答え、第二を主たる貢献として扱う。7つの設計世代を通じて、集団指導が1対1のチュータリングと同等かそれを上回ること — ブルームの予測とは逆 — を繰り返し見出した。そして見かけの効果量が、教育とは何の関係もない方法論的選択に極端に敏感であることも見出した。自分たちのコードに対する独立監査は、それ以前の結果を膨らませていた5つの交絡ファミリを明らかにした。それらを是正したのち、最も厳密な実験では教育条件が副次的な要因(10ポイントの差)にとどまり、学習者エージェントの*認知プロファイル*(38ポイントの差)に大きく引き離された。

本研究の貢献は以下のとおりである。

- エージェントによる理論検証のための**再利用可能なパラダイム**。学習は、事前知識の影響を受けない合成ドメイン上で、メモリのみによる評価プロトコルのもとでのメモリ形成として操作化される(§4)。
- 設計上の決定がいかに結論を変えたかを記録した**7世代のケーススタディ**。再現性のため、すべての run 識別子、標本サイズ、トークンコストを報告する(§5)。
- エージェント実験のための**交絡の分類(F1–F5)と是正レシピ(A-codes)**。疑似反復された単一の討論を真に反復されたものへ変換する*母集団増殖*設計と、前提知識を統制する *readiness ゲート*を含む(§6)。
- この環境におけるブルームの2シグマ問題に関する**交絡統制下の否定的結果**、および学習者プロファイルの異質性が教育条件を上回るという知見(§7–§8)。

適用範囲については明示的である(§9)。LLM エージェントが人間の学習者であるとも、Zarn Tokens が実在のカリキュラムに似ているとも、ブルームの理論が人間について偽であるとも主張しない。主張するのはもっと狭く、それゆえ有用だと考えることである。すなわち、この理論の*素朴な*エージェント検証は強いが偽の効果を生むこと、そして信頼できる帰無結果を得るには、エージェントシミュレーションの文献がまだ標準として扱っていない統制が必要であることだ。

## 2. 関連研究

**擬似的な人間被験者としての LLM。** 近年の研究は LLM を用いて調査回答者、経済ゲームのプレイヤー、社会エージェントの母集団を模擬し(Argyle et al., 2023; Aher et al., 2023)、創発的行動をデータとして研究する「生成エージェント」社会を構築している(Park et al., 2023)。並行する研究の流れは、そうしたシミュレーションが*戯画化された*あるいは分布的に狭い振る舞いを示しうること、プロンプトとサンプリングの選択が結果を左右すること、見かけの現実らしさが基盤となる機構の不在を覆い隠しうることを警告している。本研究は後者の警告に対する具体的で監査可能な一事例を寄与する。理論と整合するように見える大きな効果を生みながら、反復と交絡統制のもとで霧散したエージェント実験である。

**ブルームの2シグマ問題と現代における受容。** ブルーム(1984)の原初の主張は「1対1のチュータリングと同等に効果的な集団手法の探索」を動機づけ、知的チュータリングシステムや教育における AI の研究で日常的に引用される。その後の人間を対象とした研究は2シグマという数値を複雑にしてきた(チュータリングの効果量は通常より小さく、マスタリー学習、フィードバック、学習時間がそれぞれ寄与する)。本研究は人間を対象とした文献を裁定しない。エージェントの実験装置が操作できる対象として、理論の*構造的*形式を用いる。

**計算機実験における内的妥当性。** 疑似反復 — 独立でない測定を独立な反復として扱うこと — は生態学と行動科学における古典的な脅威であり(Hurlbert, 1984)、エージェントシミュレーションにおいては広範かつ十分に認識されていない脅威であると論じる。相互作用のトランスクリプトを1本生成し、それを多数の「学習者」が読んだものを標本として扱うことは、あまりにも容易だからである。同様に、単一インスタンスの「役割」エージェント(教師1人、判定者1人)は、操作変数を特定の生成ペルソナの特異性と交絡させる。F1–F5 の分類はこれらを含む脅威を、LLM エージェントによる教育実験に合わせたチェックリストにまとめたものである。

**LLM 採点における評価のアーティファクト。** 自由記述のモデル出力に対する完全一致採点が、意味的に正しい解答を過小評価することは知られている(Rajpurkar et al., 2016)。本研究は具体的な事例 — 帰納タスク「L6」が3世代にわたって 0% を記録した件 — を記録する。帰無を生んだのはエージェントではなく完全一致の採点器であり、いつ意味的判定者が必要になるかを論じる。

## 3. ブルームの理論の操作化

ブルームの議論には、エージェント実験が独立に操作できる3つの構造的レバーがある。

1. **集団サイズ** — 1人の指導者の注意が 1、2、…、N 人の学習者に分割される度合い。
2. **個別化** — 指導が特定の学習者の誤りに適応するか(診断 → 訂正 → 再テスト)、一律に提供されるか。
3. **能動的関与/Ownership** — 学習者が「指名され」、発言し、フィードバックを受けるか、それとも受動的に講義を受けるか。

ブルームは、小さな集団サイズ、高い個別化、高い関与が合わさって2シグマの向上を生むと予測する。本研究の各世代はこれらのレバーを異なる組み合わせで検証する。初期の世代(v4–v6)は 1:N の教室と1対1のチュータリングを対比し(レバー1+2)、機構検証(v7)は関与と個別化を切り分け、後期の世代(v8–v9c2)は共通の講義を固定したうえで*講義後*のフェーズで集団サイズと Ownership を変化させる(レバー1+3)。最後の形式は、マスタリー学習の「反転授業」的な読みに最も直接的に対応する。

決定的な操作上の判断は、何をもって「学習」とするかである。重みのファインチューニングは**行わない**。学習を、教育フェーズにおけるコンパクトな**メモリ**オブジェクトの生成として操作化し、評価時にはエージェントがそれに依拠しなければならないようにする — ルールは評価プロンプトから取り除かれる(§4.2)。したがって条件の差は、各教育形式が誘発する*メモリの内容と構造*の差として現れ、そのメモリに依存する下流のタスク正答率として現れる。これは意図的に控えめな学習の捉え方だが、「学習」と「ルールを読むこと」を交絡させずにエージェントの実験装置が測定できるのはこの形である。

## 4. Zarn Token パラダイム

### 4.1 事前知識の影響を受けない合成ドメイン

モデルが事前学習からタスクを解くことを防ぐため、いかなる学習コーパスにも存在しない閉じた採点体系 **Zarn Tokens** を考案した。色付きトークンの列が、相互作用する4つのルールと1つの重ね合わせルールによって採点される。

| トークン | 基底値 | ルール |
|---------|-------|-------|
| Red | 3(下記参照) | **修飾子のみ。** Red 自身の寄与は常に 0。すぐ右のトークンの基底値を2倍にする。 |
| Blue | 5 | **条件付き。** 左側の*どこかに*少なくとも1つの Green がある場合にのみ有効(5)。そうでなければ 0。 |
| Green | 2 | **位置依存。** 最後以外のどの位置でも有効(2)。列の最終トークンなら無効(0)。 |
| Yellow | 7 | **常に有効**(7)。位置にも隣接トークンにも依存しない。 |

**重ね合わせルール:** *無効な*トークンを2倍にしても 0 のままである(例: Green のない `[Red, Blue]` は 10 ではなく 0)。意図された評価手順は*まず有効性を判定し、次に修飾子を適用する*ことであり、この手順順序の要請が学習者タイプの1つを検証する手がかりとなる(§4.3)。

このドメインは1回の講義で教えられるほど小さく、しかし難易度の階梯を支えるだけの豊かさがある。条件付き活性化(Blue)、位置による無効化(末尾の Green)、修飾子の合成(Red の2倍化)、そしてこれら3つすべての相互作用(無効トークンの2倍化)である。例題: `[Green, Red, Yellow, Blue]` → Green 有効(2)、Red が Yellow を修飾、Yellow が2倍(14)、Blue は左に Green があるため有効(5) → **21**。

### 4.2 メモリのみによる評価プロトコル

各評価タスクは2つのフィールドを持つ。ルールを**取り除いた** `learner_prompt` と、自動採点器のみが**使用する** `hidden_rules` である。学習者は教育フェーズで形成されたメモリから答えなければならず、「*あなたが覚えているルールだけを使いなさい。教わっていないルールを仮定してはいけません*」という明示的な指示が与えられる。この分離がこのパラダイムの方法論的核心である。最初のパイロット(v1)では評価タスクにルール文は一切含まれていなかったが、メモリ形成が無制約だった(語数予算もルール露出の制限もない)。教師の講義がドメインのルールをほぼ逐語で復唱し、トランスクリプトがそれをほぼ無傷でメモリへ運び、solver はルールブックの写しに等しいメモリから答えた — 全条件が 100%(完全な天井)となったが、その経路は当初の想定とは別のものだった。v2 ではさらにルールが評価タスクのプロンプト文に直接埋め込まれ、第2の、より直接的な経路で同じ天井を再現した。どちらの経路も教育効果を覆い隠す。評価プロンプトからルールを除去し(v3 以降)、`learner_prompt` と `hidden_rules` を分離したことで、教育なしのベースラインは(ほぼ)0% まで低下し、測定可能な分散が開いた。

### 4.3 生成後のメモリ制約としての学習者タイプ

メモリオブジェクトは、モデルが教育トランスクリプトから生成する構造化された成果物である。7つのフィールドを持つ。

```json
{
  "rules": [], "examples": [], "edge_cases": [], "strategy": [],
  "corrected_misconceptions": [], "remaining_misconceptions": [], "uncertain_rules": []
}
```

評価時に学習者が推論の根拠とするのは、トランスクリプトではなくこのオブジェクトである。したがって条件間の「学習の差」とは、これらのフィールドの内容の差にほかならない。

初期に繰り返された失敗(v5)は、*プロンプトレベル*の学習者ペルソナ(「能力が低い」「エッジケースを忘れる」)が振る舞いをほとんど変えなかったことである。基盤となるモデルの能力が固定されているためだ。v6 以降は代わりに、**モデルが生成したあとのメモリオブジェクトに硬い制約を課す**ことで、理論駆動の学習者タイプを得た。

| タイプ | メモリ予算 | エッジケース保持率 | ルール順序保持率 | 質問する確率 |
|-------|----------|-----------------|---------------|-----------|
| rule_extractor | 150語 | 90% | 90% | 30% |
| edge_case_dropper | 120語 | 10% | 70% | 20% |
| order_confused | 100語 | 60% | 20% | 40% |
| passive_listener | 80語 | 20% | 40% | 0% |

(さらに3つのタイプ — help_seeker、answer_first、example_memorizer — が v6 で定義され初期の世代で使用された。)制約は機械的に適用される。エッジケースの各項目は確率 `1 − 保持率` で独立に削除される。確率 `1 − rule_order_retention` で格納されたルールリストがシャッフルされる(これは*列挙された*ルールの順序を変えるだけであり、§9 に記すとおり、解法手順は劣化**させない**。手順はメモリが別に保持する `strategy` フィールドにあり、この制約はそこに触れない)。続いてメモリは語数予算まで、優先度の低いフィールドから削って切り詰められる。そして質問確率 0 の `passive_listener` は討論で一度も発言しない(そのターンはモデル呼び出しなしでスキップされる)。これらの制約により、学習者の異質性は演技ではなく**表現のレベルで実体を持つ**。

### 4.4 フェーズ構成

成熟したプロトコル(v8 以降)は4つのフェーズで走る。

1. **講義(フェーズ1)。** 共通の教材。初期の世代は run ごとにモデルが講義を生成していたが、v9c からは単一の充実した参照講義(6,493字、5つの例題、エッジケースのチェックリスト、よくある誤りの表)を固定し、講義の質を条件間で一定に保つ。
2. **Readiness チェック(フェーズ2)。** 短い診断(v8 では3問、v9c 以降は recall、edge_case、rule_interaction、procedure_order の4タイプ)。各学習者を自動採点し、誤答には訂正ノートをメモリへ追記する。v9c からは **readiness ゲート**を加えた。集団が 80% の通過率に達しない場合 `readiness_failed` フラグが立ち、前提知識が確立**されていない**こと、そしてそれ以降の条件比較が交絡していることを示す。
3. **条件固有の相互作用(フェーズ3)。** 操作されるフェーズ。世代に応じて、講義のみ対さまざまな集団サイズの討論、あるいはチュータリングとなる。
4. **評価(フェーズ4)。** ブルーム型の階梯にまたがる、メモリのみによる10タスク。

### 4.5 タスク、採点、指標

評価の階梯は10タスクからなる。`recall`(L1)、`edge_case` ×2(L2)、`rule_interaction`(L3)、`debugging` ×3(L4/L4/L5)、`short_rule_induction`(L6)、`peer_error_detection`、`explanation_choice` である。数値と選択式の解答は隠された正解との**完全一致**で採点する。閉形式の9タスクについてはこれで信頼できるが、§6 で詳述するとおり自由記述の帰納タスク(L6)では大きく破綻する。L6 は最終的に主要スコアから除外し、意味的判定者へ回すこととした。

正答率のほかに以下を記録する。**Ownership** スコア(発言数、指名された割合、フィードバックを受けた割合)、**誤概念の訂正**率(診断された誤概念がその後のメモリから消えたか)、10項目の**メモリカバレッジ**ベクトルと討論前後の**差分**、**確信度の校正**(高確信での誤答率)、そしてフェーズごとの完全な**トークン集計**である。トークン集計が重要なのは、チュータリングと大規模討論の条件が講義のみより遥かに高価であり、公正な比較は正答率とともにコストも報告しなければならないからである。

## 5. 実験の推移(v3–v9c)

### 5.1 v4–v6: 教室対チュータリング、そして均質化効果

| 世代 | run_id(先頭) | 条件と主要正答率 | 要点 |

### 5.2 v7: 機構の検証

v6 の逆転を説明しようとする2つの的を絞った実験を行った。

- **v7a(passive_listener の救済。`dd2fd888`):** チュータリングが受動的な学習者を助けるのは*強制的な相互作用*によってか、*個別化*によってか。条件: 公開Q&A講義(88%)、強制確認つき講義(53%)、1対1(50%)。強制確認 ≈ 1対1(3ポイント差)は、利益が接触であって個別化ではないことを示唆した — しかし講義長の非対称性(紛れ込んだ「200語以内」制約により確認条件の講義が 3,599字に対し 1,022字へ短縮された)が比較を交絡させており、最も充実した*受動的*講義が最高得点となった。
- **v7b(order_confused への介入。`32ffaa49`):** 手続き的に混乱した学習者に対して、手順を足場かけしたチュータリングは generic なチュータリングに勝るか。条件: 公開Q&A(69%)、generic チュータリング(47%)、手順足場かけチュータリング(41%)。足場かけは助けにならず、わずかに害となった。generic チュータリングは誤概念訂正 100% に達しながら正答率 47% — ここでも訂正は成果と乖離した。`order_confused` の二峰性の分布(1名が 0/8)により n=4 の条件平均は不安定だった。

v7 の機構検証は否定的結果を補強する一方で、n=4 の条件平均がいかに脆いか、そして付随的なプロンプトの差(講義長)がいかに容易に教育効果を装いうるかを露わにした — 正式な交絡監査を予告するものだった。

### 5.3 v8–v9c: 反転学習、クラスサイズ、そして readiness の問題

v8 から反転設計を採用する。全条件に*共通の*講義を与え、その後のフェーズを操作する。

|-----|--------------|---|-----------------|------|
| v8 | `ef107ef9` | 16 | 全体討論 **83%**、1対1 78%、講義のみ 70%、小グループ 68% | 討論 ≥ 講義。ただし講義長が条件によって異なる |

v9b はクラスサイズ設計(2/4/8/16名のクラスを生成。§6 の*母集団増殖*による反復設計とは別物であり、後者は v9c2 で初めて登場する)と明示的な Ownership 指標を導入し、クラスサイズの単調効果も Ownership と成果の相関も見出さなかった。講義のみが最小の討論条件と首位で並び、討論によるメモリの「差分」はほぼ 0 だった(エージェントは討論から新しいルール知識をほとんど獲得しなかった)。v9c は講義を固定し4タイプの readiness チェックを加え — そして全プログラムで最もブルームに好意的な数値を生んだ。37ポイントの差で、すべての討論条件が講義のみ(28%)を上回った。ここで止めて討論の優位を報告したくなるところである。

## 6. 交絡の分類と是正

自分たちのパイプラインに対する独立監査を実施した(コードと run ごとのデータベースに対する新規の分析パスであり、公開する2つのスクリプト `check_replication.py` と `check_confounds.py` を用いた)。監査はバージョン横断の監査表と5つの交絡ファミリ(F1–F5。F5 は F5a/b/c に分解される)を生み出した。これらをエージェントベースの実験のための再利用可能なチェックリストとして、実装した是正コード(A-codes)とともに提示する。A-codes は v9c2 実装計画におけるプロジェクト内部の変更IDであって、あとから導出し直した連番ではない。したがって非連続(A0, A3, A4, A5, A6, A8)であり、F-codes と数値的に**対応しない**。付録 B に交絡→是正の明示的な対応表を示す。見た目の整合のために改名するのではなく、論文が公開コードと一致するよう元のIDを保持する。

**F1 — 静的な訂正フィードバック。** readiness チェックの誤答には、*固定の事前記述*された訂正ノートがメモリへ追記される。どの誤概念が誤りを引き起こしたかにかかわらず同一である。これは合否の採点を歪めないが(採点はノートより先に行われる)、「適応的フィードバックが学習を駆動した」というあらゆる主張の根拠を崩す。*状態:* 設計上の限界として認識。完全には是正されていない(LLM が誤りごとに生成するノートが正しい修正であり、今後の課題として残る)。

**F2 — 完全一致採点のアーティファクト → A8。** 自由記述の帰納タスク(L6、*short_rule_induction*)は v8、v9b、v9c で 0% を記録した。キュレートした別名による再採点でもほとんど回復せず汎化もしなかったが、検査の結果、エージェントは*意味的に正しい*ルール記述を生成しており、それを完全一致採点器が棄却していたことが確認された。これはエージェントの失敗ではなく評価のアーティファクトである。*是正 A8:* L6 を主要スコアから除外し、LLM による意味的判定者(`SEMANTIC_TASK_TYPES`)へ回す。以降の run 向けに実装済み。(閉形式の9タスクは影響を受けず、完全一致のままである。)

**F3 — 討論への文脈が注入されない → A0。** 討論フェーズにおいて、*参加者*エージェントは講義文も自分の事前メモリもプロンプトで受け取っていなかった。受け取っていたのは司会者だけである。トランスクリプトを確認すると、指名された学習者は文字どおり「I don't actually know the rules(実はルールを知らない)」と切り出していた。したがって条件間の差は、協働的な知識構築ではなく、*エージェントが空の文脈からどう即興するか*を部分的に測っていた。*是正 A0:* 各学習者のメモリを発言および応答のプロンプトへ注入し、参加者が自分の知っていることから推論するようにした。

**F4 — 疑似反復 → A3。** これが最も帰結の大きい交絡である。v4–v9c では、各討論/教室条件が生成するトランスクリプトは**1本**だった(`unique_discussions = 1`)。その条件の複数の「学習者」は、すべてその単一の会話の読み手にすぎない。したがって条件ごとの標準偏差は、N=1 の出来事に対する学習者の反応の分散を反映しており、教育設計についての不確実性では*ない* — にもかかわらず、それはまさに「条件 A > 条件 B」を(誤って)主張するために使う量である。*是正 A3:* **母集団増殖**設計により、条件ごとに `n_disc`(=5)本の*独立した*討論を、それぞれ新たにサンプリングした学習者とともに生成し、討論レベルで集計する。これは疑似反復を真の反復へ変換するものであり、エージェントベースの社会実験にとって単一で最も重要な統制であると考える。

**F5a — 学習者プロファイルの均質性 → A4(既に充足)。** 学習者母集団が多様かどうか。v7a/v7b は意図的に単一のタイプを用いた(交絡ではなく範囲を絞った選択である)。v8/v9b/v9c は既に均衡した4タイプを用いていた。*状態:* v8 以降は充足。「全学習者が1タイプだった」という誤った監査注記は、スモーク設定のデータベースに由来することが判明し訂正された。

**F5b — 単一インスタンスの役割エージェント → A5。** v4–v9c のすべてにおいて、`classroom_teacher` 1体、チューター1体、evaluator 1体がすべての条件を担当していた。したがって操作変数は、単一の生成ペルソナ/判定者の特異性と交絡している。*是正 A5:* `n_disc` 本の独立した討論それぞれに新しい教師エージェントを割り当てる(5人の異なる教師)。evaluator は意図的に三重化**しなかった**。残した9タスクが完全一致で採点されるため採点経路が LLM 判定者に到達せず、evaluator を複数化しても no-op になるからである(L6 の意味的判定者が使用されて初めて意味を持つ)。

**F5c — 学習予算の非対称 → A6。** 講義のみの学習者はフェーズ3のセッションがゼロで、討論の学習者は1つあった。したがって「講義のみ対討論」は*形式*を*講義後の学習機会の量*と交絡させていた。*是正 A6:* **自己省察フェーズ**により、講義のみの学習者に構造化された個人省察のセッション — 種類において対応する*追加の学習機会* — を与える(ただし率直に報告するとおり、トークン量においては対応していない。§7 と §9 を参照)。

バージョン横断の監査表(成果物として公開)は、v4–v9c2 の各世代について run-id とデータベースの対応、条件ごとの `sessions` 対 `unique_discussions` の数(F4)、単一インスタンス/多様性の状態(F5)を記録している。その要約行列は、**F4 が v9c までのすべての世代に存在し、v9c2 で解消された(条件あたり5本の独立した討論)**ことを示す。F5b は v4–v9c のすべてに存在し、v9c2 で部分的に是正された。したがって2つの構造的交絡は*最初の実験から作り込まれており*、監査が捉えるまで6世代の結果を静かに形作っていた。(v8 は当初、部分的な例外に見えた。共通の前提講義を操作フェーズから切り離すと、全体討論の条件は F4 の完全な事例であり — 1本の討論を4名の学習者が共有していた — 1対1の条件は完全に反復されていたことが分かった。フェーズを区別せずに `learning_sessions` を数えたことが差を圧縮していたのである。)これが本論文の警句的な核心である。交絡は「コードが走り、もっともらしい数値を出す」というレベルでは不可視であり、反復と独立性の監査によってのみ表面化した。

## 7. v9c2: 交絡を統制した実験

v9c2 は A0/A3/A5/A6/A8 をまとめて適用し(A4 — 学習者プロファイルの多様性 — は v8 以降すでに充足していることを検証した)、統制のもとで v9c の問いを問い直す。(run_id `dc1bdd27`、`claude-sonnet-4-6`、学習者154名、2,376,593トークン。)

**設計。** 5条件。`lecture_plus_self_reflection`(n=4。A6 で是正し改名した講義のみ)と4つの討論サイズ — ペア(2)、小(4)、中(8)、大(16) — であり、各討論サイズは `n_disc = 5` 本の独立した討論と討論ごとに新しい教師による母集団増殖で実現される。均衡した4つの学習者タイプ。共通の固定講義。80% ゲートを備えた4タイプの readiness チェック。

**readiness ゲートを通過した。** 集団は readiness **90%** に到達した(edge_case 100%、recall 91%、procedure_order 85%、rule_interaction 85%)。ゲートを越えた最初の世代であり、条件比較が前提知識を真に保持した学習者について測られたのはこれが初めてである。

**主要結果 — 効果は崩壊する。**

| 条件 | 正答率 | 教育トークン | 教育トークン1kあたり正答数 |
|------|-------|-----------|----------------------|
| lecture_plus_self_reflection | 83% | 2,716 | 11.05 |
| pair_discussion_size_2 | 80% | 45,775 | 1.57 |
| small_class_discussion_size_4 | 76% | 42,590 | 3.19 |
| medium_class_discussion_size_8 | 86% | 41,580 | 7.46 |
| large_class_discussion_size_16 | 81% | 35,035 | 16.67 |

教育条件間の差は **10パーセントポイント**(中 86% 対 小 76%)であり、v9c の 37 から縮小した。そして順序はクラスサイズについても Ownership についても非単調である。実験装置が算出する interpretation flags は `class_size_effect_supported = false`、`ownership_effect_supported = false`、`discussion_added_value = false` である。これらのフラグは*閾値*テスト(効果が講義ベースラインに対し一定の margin を超えなければならない)であって有意性検定ではないことを強調する。正直な読みは「*大きな*効果はない」であって「ちょうどゼロ」ではない。実際、数値上の首位は討論条件(中、86%)であり、lecture-plus-self-reflection(83%)を1ポイント上回っている — したがって討論が*害になる*とは主張せず、どの条件も意味のある margin を超えないこと、そして v9c の「討論の優位」(すべての討論条件が 28% の講義ベースラインを遥かに上回った)が readiness の統制と反復のもとで**生き残らなかった**ことのみを述べる。

**学習者タイプが支配する。** 学習者*タイプ*間の差は **38ポイント**(edge_case_dropper 96% 対 passive_listener 58%)であり、条件間の差のほぼ4倍である。条件比較について慎重にさせるのと同じ n において、このより大きく方向の安定した開き(最もメモリ制約の強いタイプである passive_listener が v6、v9b、v9c2 で最下位、v9c で最下位タイ)は、より擁護しやすい比較の主張である。下流の正答率を決める最大の要因は、教育形式ではなく認知プロファイル(メモリ制約)なのである。v9c の学習者タイプ差はわずか8ポイントだった。より大きく readiness を統制した標本では、プロファイルの差がはるかに明瞭に解像する。ただしこれも検定された効果ではなく差として報告する(§9)。

**トークン効率は「何が勝ったか」を捉え直す。** A6 は講義のみの学習機会を*種類*において対応させたが*量*においては対応させなかったため、lecture_plus_self_reflection の教育トークンは約2.7kで、討論条件の35–46kに対して少ない。したがって1kトークンあたりの学習効率では、講義のみ(11.05)と大クラス(16.67)がペア/小討論(1.57/3.19)を大きく上回る。2つの留保がある。大クラスがこの指標で最高なのは、1人の教師のトークンが16名に償却されるからにすぎない — これは1人あたりの指導コストの記述であって学習の質の記述ではなく、大人数クラスを推奨するものと読んではならない。そして同じ指標が v9c2 に残る主要な交絡(§9)を露わにする。A6 は「等しい学習機会」を構造的には達成したが(省察セッション)、計算量では達成しなかった(約1/15のトークン)。したがって講義のみの 83% は、どちらの予算を固定するかによって、驚くほど安価とも不当に資源が乏しいとも読める。頑健な言明はより弱いほうである。**トークン消費が1〜2桁の範囲で変動しても、下流の正答率はせいぜい10ポイントしか動かなかった。**

## 8. 横断的な知見

1. **教育の効果は本物である。** 教育なしのベースラインは全世代で 0% にとどまり、パイプラインは確かに学習を測定している。教育フェーズを受けないエージェントはまったく答えられず、教育を受けたどの条件もそれを遥かに上回る。この先に何が続くにせよ、この測定器は教えることの有無を検出している。

2. **クラスサイズは成果を予測しない。** 順序はこれを変化させたすべての世代で非単調である — v9b: 講義のみ = ペア(60%)> 小 48% > 大 47% > 中 45%。v9c: ペア 65% > 小 57% > 大 52% > 中 40%。v9c2: 中(8名)86% > 大(16)81% > ペア(2)80% > 小(4)76%。「小さいほど良い」もその逆も生き残らない。`中` の条件は3世代連続で討論条件の*最低*であり、統制された世代では*最高*となった。これ自体、以前のパターンがクラスサイズではなく交絡を追っていたことの証拠である。

3. **Ownership は成果を予測しない。** Ownership — 学習者が指名され、自分の推論を言語化しなければならない度合い — は 0.56(大クラス。発言する学習者は19%)から 3.0(ペア。全員が発言)まで変化するよう設計され、この操作は検証可能な形で機能した。発言率はすべての世代で設計どおりである。成果はそれに従わない。v9c2 で最高得点の条件は Ownership 1.5 の `中` であり、次点は 0.56 の `大` である。一方 Ownership 3.0 の2条件(ペア、小)はいずれもそれらを下回る。**最もよく発言する学習者が、最もよく得点する学習者ではない。**

4. **討論は個人の省察に対して測定可能な付加価値を持たない。** 講義のみの学習者に対応する学習機会(A6 の自己省察フェーズ)を与えたところ、彼らは 83% を記録した — 4つの討論条件のうち3つを上回る。上回るのは `中` のみであり、その差は3ポイントで、実験装置が付加価値を認定するのに要する5ポイントの margin を下回る。v9c で*すべての*討論条件が 28% の講義ベースラインを大きく上回ったパターンは、readiness の統制によっても学習予算の非対称の除去によっても生き残らなかった。

   知見2–4 が否定的結果の実質である。ブルームの説明が依拠する3つの構造変数 — 集団サイズ、個人の関与、そして社会的相互作用そのもの — は、前提知識が統制され討論が真に反復された唯一の世代において、いずれも学習を予測しなかった。これらを別々に述べるのは、別々に検証されたからであり、またフラグの値としてしか報告されない帰無は容易に見落とされるからである。

5. **主要な数値は教育ではなく交絡でよりよく説明される — ただしこの比較は明確な ablation ではない。** v9c→v9c2 の対比は条件差を37ポイントから10ポイントへ動かし、3つの interpretation flag を反転させた。推論については意図的に慎重である。v9c2 は6つの是正を*同時に*変更し、n を34から154へ増やしたため、崩壊をどれか1つの統制に帰属させることはできない。2つの機構は設計上部分的に絡み合ってもいる。A3(反復)は本質的に n を増やし、条件あたり `unique_discussions = 1` の上に築かれた37ポイントの差(F4)は、定義上、安定した効果ではなく単一の討論に対する学習者反応の分散だった。したがって「交絡を除いたら効果が崩壊した」と「反復を加えたら N=1 のノイズが平均化された」は、ここでは競合する説明ではなく*同じ*是正の2つの記述である。確実に主張できるのは条件文である。**反復と前提知識の統制を生き残らない差は、教育効果として報告するには安全でなかった。** 主張できないのは変数を切り分けた因果分解であり、単一統制の ablation が当然の次の実験である(§9)。実際にそのような ablation を1本走らせた — `bloom_v9c2_ablation_ndisc1`(run `a551c74d`。n_disc=1、他の v9c2 是正はすべて有効) — そして25ポイントの条件差(ペア 72% 対 講義 47%)を生み、v9c(37pp)と v9c2(10pp)の中間となった。これは反復が鍵となる要因であるという見方と整合する。ただしこの ablation の readiness ゲートは 53% で不合格だったため、前提知識もまた統制されていなかった。2つの要因が同時に変化しており、A3 単独を明確に切り分けることはできない。

6. **学習者の異質性が支配的な変数である。** 前提知識が統制されたとき、*学習者が誰であるか*(そのメモリ制約)が、*どう教えられたか*(10ポイント)より遥かに多くの分散(38ポイント)を説明する。これ自体が実質的な結果である。この環境では、教育形式は学習者の表現に次ぐ二次的な要因である。

7. **2つの頑健なミクロ機構。** (i) *均質化*: 1対1のチュータリングは成果の分布を圧縮する(最も弱いタイプを引き上げ、最も強いタイプを引き下げる)が平均は上げない。(ii) *訂正と成果の乖離*: 誤概念の訂正率が高くても正答率の向上につながらない。いずれも複数の世代にわたって成立し、人間を対象とした研究への仮説の候補であるが、ここではエージェント環境における知見としてのみ述べる。(ii) は機構を伴わない観察として述べる。以前に提示した説明 — 訂正が*手続き的*欠損を放置するというもの — は、学習者タイプの制約に対する監査を生き残らない(§9)。

8. **コストの非対称は大きく、通常は無視されている。** v9c2 では討論条件が講義/自己省察の13–17倍の教育フェーズトークンを費やし(35–46k 対 2.7k)、正答率は同等以下だった。それ以前の世代では1対1のチュータリングが教室講義の約4.3倍のコストだった(v5: 35,095 対 8,180トークン)。エージェントベースの教育に関するいかなる主張も、コストで正規化した成果を報告すべきである。さもなければ「高価な条件」は単により多くを行ったというだけで優れて見えうる。

## 9. 限界と適用範囲

主張は厳密に限定する。

- **エージェントは生徒ではない。** 測定しているのは、課された記憶制約のもとでの単一 LLM によるメモリ形成とルール適用であって、人間の認知ではない。本稿のいかなる内容も、ブルームの2シグマ効果が人間について成り立つかどうかに直接は関わらない。
- **1つのドメイン、1つのモデルファミリ。** すべての結果は Zarn Tokens と `claude-sonnet-4-6` におけるものである。この合成ドメインは事前知識の影響を受けないことを理由に選ばれたのであって、生態学的妥当性のためではない。ドメインやモデルファミリを越えた一般化は未検証である。
- **残存するトークンの非対称(生きている交絡)。** A6 は講義のみについて学習機会の*種類*を等しくしたが、そのトークン量は等しくしていない(約2.7k 対 約35–46k)。より清潔な将来の設計は、条件間で計算予算を等しくするか、予算を揃えた arm を報告するだろう。
- **単一変数の明確な ablation がない。** 要となる v9c→v9c2 の比較は6つの是正と4.5倍の標本増加を束ねている。膨らんだ効果が統制を生き残らなかったことは示せるが、どの統制が原因だったかは示せない。ablation を1本走らせた(`bloom_v9c2_ablation_ndisc1`、run `a551c74d`: n_disc=1、他の v9c2 是正はすべて有効)。25ポイントの条件差を生み、v9c(37pp、readiness 69%)と v9c2(10pp、readiness 90%)の中間となった。これは反復(A3)が鍵となる駆動要因であるという方向と整合する。しかしこの ablation の readiness ゲートは 53% で不合格であり、前提知識*もまた*統制されていなかった。両方の要因が同時に動いたため、ablation は束としての是正が効くことは確認するが、A3 単独を切り分けることはできない。より清潔な次の設計は readiness を固定し(ゲートを通過するまで複数回走らせるなど)、n_disc のみを独立に変化させるものである。
- **統計的検出力。** `n_disc = 5` であっても、条件あたり5本の独立した討論では強い推測統計的検定は支えられない。10ポイントの条件差は「ちょうどゼロ」ではなく「大きな効果はない」と読むのが最善である。同じ注意は原理的には38ポイントの学習者タイプ差にも当てはまる。それにより重く依拠するのは、それがより大きく4世代にわたって方向が一貫しているからであって、統計的に確立されているからではない。p 値ではなく記述統計と interpretation flags を報告し、確認的な run には `n_disc = 10–15` を推奨する。
- **readiness の項目が教材と重複している。** 4つの readiness チェックのうち2つ — `rc_recall_01`(`[Yellow, Green]` → 7)と `rc_edge_case_01`(`[Red, Blue]` → 0)— は、答えを含む例題として固定講義に逐語で登場する。この2項目は、ゲートを使用した両世代で通過率の上位2つでもある(v9c: edge_case 100%、recall 68% に対し procedure_order 59%、rule_interaction 50%。v9c2: 100% と 91% に対し 85% と 85%)。重複が通過率を*駆動している*とは主張しない — 同じ兆候は評価タスクには再現せず、同様に重複する項目(`l2_edge_case_01`)は v9c で 17.6% だった — が、少なくとも edge_case と recall については §7 の「前提知識を真に保持していた」という表現を弱める。これらの項目は、講義が与えた答えを再生することで通過できるからである。清潔なゲートは、教材に存在しない列から項目を引くべきである。
- **L6 の意味的判定者の判定がスコアに届いていない。** A8 には2つの半分がある。L6 を主要スコアから除外することと、LLM 判定者へ回すことである。前半は機能している。後半は報告値に到達していない。`answer_correct` は完全一致経路(`lib/scorer.rb`)でのみ設定され、`lib/phases/evaluator.rb` の LLM 分岐は一度も設定しない。ablation のスモークデータベースでは、L6 の行は `auto_scored = 0` と判定者の合計点 20点中11–20点を持ちながら `answer_correct` が null である — したがって下流の集計はすべてそれらを誤答として読み、L6 付録は依然として 0 を印字する。修正は数行だが適用には再実行を要する。その結果、**本稿が報告するいかなる世代にも検証済みの L6 測定値は存在しない**。すべての run report の L6 の数値は「0%」ではなく「未測定」と読むべきである。
- **4つの学習者タイプのうち1つは一度も具現化されていなかった。** `order_confused` は `rule_order_retention = 0.2` で定義され、格納された `rules` 配列のシャッフルとして実装されている。この配列は事実のリストであり、解法手順は別の `strategy` フィールドにあって、制約はそこに触れない。v7b — すべてこのタイプで走らせた世代 — を検査すると、12名の学習者全員が、手順の教示を受けなかった8名を含めて、`strategy` に「有効性を確認し、次に修飾子を適用する」という正しい順序を保持していた。したがって意図された手続き的欠損はそもそも存在せず、この run の手順順序エラー検出器が全条件で 0% を報告したのもそのためである。帰結は2つある。*手続き的*欠損に依拠するいかなる主張も撤回する(§5.1、§8)。そして v7b は、どの学習者も持っていない欠損に対して介入を検証していたことになる。v9c2 の学習者タイプ差は影響を受けない — その両端は `edge_case_dropper`(96%)と `passive_listener`(58%)であり、`order_confused` はその間の 77% である — が、このタイプのラベルは操作された内容を過大に表している。適切に操作化するには、構成概念が実際に宿っているフィールドを制約する必要がある。
- **F1 は未解決。** 訂正フィードバックは静的なままであり、誤りごとに適応するフィードバックは未実装である。
- **確率過程はシード統制されていない。** 学習者タイプの制約(確率的なエッジケース削除、ルール順序のシャッフル)と LLM のサンプリングは固定の RNG シードなしで走るため、run はビット単位で再現可能ではない。分析は各 run の凍結された出力から決定的に再生成されるが、厳密な再実行は異なる結果になる。シードを固定した制約適用は次の世代で計画している。その変動の規模は具体的に述べておく価値がある。世代間のいかなる比較が何を担えるかを画定するからである。**同じ**固定講義と**同じ** readiness チェックを用いながら、`rule_interaction` の通過率は v9c で 50%、v9c2 で 85%、ablation で **12%** だった — n=34 において二項標準誤差の4〜5倍の幅であり、サンプリングだけに帰すことはできず、それ以外の説明もできていない。関連するパターンとして、readiness ゲートが不合格だった2つの run(v9c は37ポイント、ablation は25ポイント)は、いずれも差の両端に同じ2条件 — 2名のペアと4名の講義条件 — を持つのに対し、統制された run ではそうならない(v9c2 は中の 86% から小の 76% まで)。初期の大きな差を生んだものが何であれ、それは readiness の統制を生き残らなかった。しかしそれを切り分けられてもいない。
- **AI 著者性の再帰性。** 前書きで開示したとおり、本研究は実験の被験者と同じモデルファミリの LLM エージェントによって、人間の著者の指示とレビューのもとで設計・実行・執筆された。共有された盲点 — 監査する側と監査される側が同じ基盤を共有している — の潜在的な源としてこれを明示し、交絡監査(§6)自体がエージェントによって実行されたことを記す。監査の独立した人間による再現が、当然の外部チェックである。
- **「学習」という構成概念。** メモリのみの評価は意図的に狭い操作化である。より豊かな構成概念(転移、セッションをまたぐ保持)は適用範囲外である。

これらの未解決項目は成果物の強みだと考える。それぞれが記録され、コード上の位置が特定され、次の世代に向けて優先順位づけされている。これはエージェントによる理論検証一般に対して推奨する姿勢である。

## 10. 結論

LLM エージェントがブルームの2シグマ問題の検証台になりうるかを問い、2つのレベルで答えた。実質的には、この環境では理論の社会的相互作用の優位性は再現しない。交絡統制のもとでは教育形式は副次的な要因(10ポイントの差)であり、学習者の認知プロファイル(38ポイントの差)に支配され、社会的な条件は正答率の向上なしに遥かに高価である。方法論的には — そしてこちらが特定の結果より長く残ると期待する貢献だが — 同じ実験の*素朴な*版が大きく理論に好都合な効果(37ポイントの差、「討論には価値がある」)を生みながら、反復と前提知識の統制を**生き残らなかった**ことを示した。過剰な帰属は慎む。統制を同時に適用したため、示したのはその効果が報告するには安全でなかったことであって、どの交絡がそれを作ったかではない。脅威を5ファミリの交絡分類(F1–F5)と是正レシピ(A-codes)へ蒸留した。中心にあるのは真の反復のための母集団増殖設計と、前提知識の統制のための readiness ゲートである。

「LLM を擬似被験者とする」試み全般に対するより広い教訓は、厳しくはあるが、建設的なものであってほしいと願う。**エージェント実験は、きれいに走り、もっともらしい数値を出し、それでもなお間違ったものを測っていることがありうる。** 明示的な内的妥当性の統制の*あとに*得られた否定的結果は、その前に得られた肯定的結果より有益である。コード、設定、バージョンごとの分析、run ごとのデータベースをすべて公開し(ablation run のデータベースは紛失したため、生成された run report を verbatim で公開する)、交絡チェックリストと、この警句的な物語が再利用できるようにする。

## 付録C. 再現性

各世代にはバージョン固定の設定(`experiments/bloom_1n_vs_1on1/config/config_v*.yml`)と実行スクリプト(`scripts/run_experiment_v*.rb`)がある。レポートは凍結された run データベースから `scripts/regen_report.rb` で再生成される。監査スクリプト `check_replication.py`(条件ごとの `unique_discussions` を数える)と `check_confounds.py`(単一インスタンスとプロファイル多様性のチェック)はバージョン横断の監査表を再現する。ただし `check_replication.py` はフェーズを区別せずに `learning_sessions` をハッシュ化するため、共通の前提講義を持つ設計では条件ごとの数をフェーズ単位で読む必要がある(§6)。

§7 に引用した interpretation flags は `lib/report.rb` で算出される閾値テストであり、`false` を読むにはその定義が重要である。`class_size_effect_supported` は討論条件がサイズについて*厳密に*単調減少である場合にのみ true となる — 1箇所でも逆転すれば false であり、4条件が偶然に厳密な順序で並ぶ確率は約4%なので、`false` は帰無のもとでもノイズを伴う真の効果のもとでも期待される値である。`discussion_added_value` は*いずれか*の討論条件がベースラインを5ポイント超えれば true となるため、小さな条件1つがこれを立てうる。`ownership_effect_supported` は条件間で concordant 対 discordant のペアを比較する。いずれも有意性検定ではない。

Zarn Token の参照講義、評価タスク、ルーブリックは `domains/zarn_tokens/` に収録されている。
