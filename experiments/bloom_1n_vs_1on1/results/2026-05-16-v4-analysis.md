## 1. 実験の目的

Bloom's 2 Sigma Problem（Bloom, 1984）を LLM エージェント実験として翻訳し、**教育条件の違いが自律的問題解決行動に与える影響**を測定する。

特に本バージョン（v4）では以下を改善した：
- **memory-only 評価**：評価プロンプトからルールを除去し、学習フェーズで形成された memory のみで解答させる（v3 から継続）
- **tutoring の拡張**：2 exchange（4ターン）から 4 exchange（8ターン）へ。フィードバック→学習者の反省→2回目の診断問という、Bloom 型のフィードバックループを実装
- **3条件比較**：no_education（ベースライン）・classroom（1:N授業）・tutoring（1on1）
- **L5 タスク再設計**：純粋論理で解ける counterexample を、ドメイン知識依存の debugging に変更

## 4. 考察

### 4.1 主要発見：Bloom 仮説は（この実験では）支持されない

**classroom（47%）> tutoring（28%）> no_education（0%）** という逆転が生じた。

この結果は、v3 のスモークテスト（n=1）でも観察された傾向と一致する。しかし n=4 でも同じ方向性が出たことから、偶然の揺れとは言い切れない。

### 4.2 教育効果は確認できた

最も重要な発見は「**教育があることで正解率が有意に上がる**」点である。

- no_education が一貫して 0%
- classroom・tutoring は 28〜47% の正解率

これは **教育フェーズで形成された memory が問題解決に寄与している** ことを示す。memory-only 評価設計（v3 以降）が機能していると判断できる。

### 4.3 classroom が tutoring を上回った理由（仮説）

#### 仮説 A：公開 Q&A の「情報集約効果」

classroom では複数学習者が異なる角度から質問し、教師がすべて公開回答する。これにより「自分では気づかなかった疑問点も学べる」副作用が生まれる。

tutoring ではこの横展開がない。自分の疑問と教師のフィードバックのみ。

#### 仮説 B：tutoring の「0/8 学習者」問題

tutoring 4名のうち 1名が 0/8（全タスク不正解）だった。この 1名が存在しなければ：
- tutoring 残り 3名の平均: (3+3+3)/3 = 3/8 = 37.5%
- classroom との差は 47% vs 37.5% = 9.5pp（縮まるが逆転は残る）

tutoring は「1on1 セッションの当たり外れ」が大きい。チューターが何を教えるかが learner ごとに異なるため、variance が高い。

#### 仮説 C：タスクとの相性

debugging タスク（L4, L5）では classroom が特に強い。
- L4: classroom 100% vs tutoring 75%
- L5: classroom 50% vs tutoring **0%**

debugging はルールの精密な適用を要求する。classroom の公開授業（ルールを体系的に説明）が、ルール適用の正確さを育てた可能性がある。

tutoring は「わかったつもり」になりやすい対話的なフォーマットのため、edge case への対応が弱くなったかもしれない。

#### 仮説 D：tutoring 時間の非対称性

tutoring は 1on1 なので教師側の attention は 1 人に集中するが、**4 exchange = 8 ターン（最大約 1600 tokens）**という制約がある。

この中で扱えるルール数は限られる。classroom は教師が全ルールを体系的に説明し、複数学習者の質問でカバレッジが広がる。

### 4.4 too_hard タスクの分析

L1, L6 が全条件 0%、L3 がほぼ 0%（classroom のみ 1/4 = 25%、他条件 0%）で、いずれも too_hard 傾向を示した。

- **L1（recall）**：[Green, Blue, Yellow] を memory だけで解くのは、ルールが memory に正確に残っていれば解けるはず。0% は memory 形成の不完全さを示す（実際、classroom の memory を確認すると `rules` に Yellow=7 と active Green=2 の基底値が欠落しており、この2値がなければ L1 は解けない）
- **L3（rule_interaction）**：[Green, Red, Blue] → Red が Blue を doubling する組み合わせ。教育でこの組み合わせを扱わなかった可能性（classroom が 1/4 だけ正解したのは、この組み合わせを扱えた学習者が1名いたことを示唆）
- **L6（induction）**：新ルール（Orange Zarn）+ 既存ルール（Green 末尾）の同時適用。memory のみでは対応困難

### 4.5 Bloom の 2 Sigma Problem との対比

| 項目 | Bloom の知見 | 本実験 (v4) |
|------|-------------|------------|
| 比較基準 | 集団授業 vs 1on1 tutoring | classroom vs tutoring |
| 効果方向 | tutoring >> classroom (+2σ) | classroom > tutoring |
| 効果量 | +2 standard deviation | classroom +19pp over tutoring |
| n | 大規模（数百人） | n=4 per condition |

Bloom の original 研究とは逆の方向性だが、本実験はドメイン知識・教育時間・学習者数が大きく異なる。**直接比較はできない**。

## 5. 方法論的考察

### 5.1 この実験で測れていること

- memory-only 評価を用いることで「教育効果」は測定可能になった ✅
- 3条件設計で「教育がある/ない」の差は明確に観測できた ✅

### 5.2 この実験で測れていないこと

- **本当の Bloom 型 mastery learning**：今の tutoring には mastery criterion がない。誤答しても続ける
- **学習の持続性**：memory が compact（最大120語）なため、細かいルールが落ちやすい
- **複数セッション**：Bloom の tutoring は複数回にわたる継続的指導だが、本実験は1セッション
- **人間の学習者との対応**：LLM は既にルール知識を持っている可能性が高い。「思い出せるか」と「学ぶ」は異なる

### 5.3 自動採点の限界

- answer_correct（正解/不正解）はバイナリ判定のみ
- 「惜しい」ミスが 0 点になる（例：L5 で tutoring が 0%）
- partial credit がないため、tutoring の actual knowledge が過小評価の可能性

## 7. 次の実験への提案

### 優先度 高

1. **n を増やす**（n=10/10/6）：現在 n=4 は統計的に不安定。1人の差が 25pp を動かす
2. **Mastery criterion の導入**：tutoring に「正答するまで教える」ループを追加し、真の mastery learning を実装
3. **tutoring variance の分析**：0/8 学習者が何を学習したか memory を精査する

### 優先度 中

4. **classroom Q&A を制限する**：現状 classroom は全員の質問を公開で答えている。これを「質問なし」条件と比較して Q&A の効果を分離する
5. **L1, L3 の難易度調整**：too_hard タスクはデータとして使えない。ルールをより覚えやすい形に変更するか、hint を1つだけ含める

### 優先度 低

6. **haiku モデルでの calibration**：Sonnet 4.6 では memory があれば解けてしまうタスクが、haiku ではより差が出る可能性がある
7. **複数ドメイン**：Zarn Tokens 以外のドメインでも同様の結果が出るか確認

## 8. 結論

**本実験の核心的知見：**

> LLM エージェント実験において、memory-only 評価設計を用いることで教育フェーズの効果を測定することは可能である。n=4 という小規模でも、教育条件間の差は観測できた。ただし Bloom の 2 Sigma Problem が示す「1on1 tutoring の優位性」は本実験では再現されなかった。

この結果は Bloom の理論を否定するものではない。現在の tutoring 実装（4 exchange, mastery criterion なし）は Bloom が想定した tutoring とは大きく異なる。本実験が示すのは「このプロトコルでは classroom の方が有効」という、プロトコル設計の問題である。

Bloom の仮説を適切に検証するには、mastery learning ループと複数セッションを実装した上で n を増やす必要がある。
